### 📌 [Q1] 동적 프로그래밍이란 무엇이며 어떤 문제에 적용 가능한가?

동적 프로그래밍(Dynamic Programming, DP)은 복잡하고 큰 문제를 여러 개의 작은 하위 문제(Subproblem)로 나누어 해결하고, 그 **결과를 메모리에 저장해 두었다가 나중에 동일한 하위 문제가 발생했을 때 다시 계산하지 않고 재사용**하는 알고리즘 설계 기법입니다.
- 주로 **최적화 문제**(최대값 구하기, 최소 비용 문제 등)나 **경우의 수**를 구하는 문제에 널리 적용됩니다. 
- (예: 피보나치 수열, 최단 경로 탐색, 배낭 문제(Knapsack Problem), LCS 등)

### 📌 [Q2] DP의 두 가지 조건(최적 부분 구조, 중복 부분 문제)을 설명하면?

DP를 적용하기 위해서는 다음 두 가지 성질을 반드시 만족해야 합니다.
1. **최적 부분 구조 (Optimal Substructure)**: 큰 문제의 최적해가 그 문제를 구성하는 작은 부분 문제들의 최적해들로 구성되는 성질입니다. 즉, 작은 문제에서 찾은 최적의 결과를 결합하면 전체 문제의 최적의 결과를 얻을 수 있어야 합니다.
2. **중복되는 부분 문제 (Overlapping Subproblems)**: 동일한 작은 문제들이 반복해서 나타나는 성질입니다. DP의 핵심은 '계산 결과의 재사용'에 있으므로, 부분 문제가 중복되지 않고 단 한 번씩만 발생한다면 DP를 통한 성능 최적화를 기대할 수 없으며 분할 정복 방식으로 풀어야 합니다.

### 📌 [Q3] Memoization(Top-down)과 Tabulation(Bottom-up)의 차이는?

두 방식 모두 중복 계산을 방지하기 위해 사용되지만 문제 접근 방향에 차이가 있습니다.
- **Memoization (Top-down, 하향식)**: 큰 문제에서 출발하여 해답을 구하기 위해 작은 문제들을 재귀적으로 호출하는 방식입니다. 수행 과정에서 한 번 계산한 결과는 캐시(주로 배열이나 해시 테이블)에 '메모'해 두고, 다음 번에 똑같은 호출이 있으면 메모된 값을 즉시 반환(재사용)합니다.
- **Tabulation (Bottom-up, 상향식)**: 가장 작은 문제들부터 시작하여 차례대로 그 결과들을 표(Table) 형태의 배열에 채워 넣어 가며(Tabulation) 점진적으로 가장 큰 문제의 해까지 도달하는 방식입니다. 주로 재귀 함수 대신 반복문(for문, while문)을 기반으로 구현됩니다.

### 📌 [Q4] 각 방식의 장단점은? 어떤 경우에 어떤 방식을 선택하는가?

**1. Memoization (Top-down)**
- *장점*: 점화식의 개념과 직관이 그대로 코드(재귀 호출)로 표현되므로 설계가 쉽고 가독성이 좋습니다. 또한, 도달하지 않는 불필요한 부분 문제는 아예 호출되지 않아 계산하지 않으므로 특정 상황에서는 더 효율적일 수 있습니다.
- *단점*: 재귀 호출로 인해 함수 Call Stack이 깊어지면 스택 오버플로우(Stack Overflow) 에러나 함수 호출 및 컨텍스트 스위칭 오버헤드가 발생할 수 있습니다.

**2. Tabulation (Bottom-up)**
- *장점*: 반복문을 사용하므로 오버헤드가 적고 처리 속도가 빠른 편이며 스택 오버플로우 위험이 없습니다. 공간복잡도 최적화(예: 배열의 전체를 유지하지 않고 최근 몇 개의 값만 유지)하기가 수월한 경우가 많습니다.
- *단점*: 규칙을 파악해 반복문 형태로 구현하기 위한 초기 설계 논리를 짜기가 직관적인 하향 방식보다 조금 더 까다로울 수 있습니다. 또한 답을 얻기 위해 필요치 않은 일부 하위 문제 구간까지 전부 순서대로 계산해야 할 수 있습니다.

**선택 기준**: 보통은 로직 설계가 익숙한 방식으로 진행합니다. 제약 조건이 빡빡하지 않으면 점화식을 그대로 옮기기 쉬운 Top-down 방식으로 먼저 짜볼 수 있으나, 알고리즘 테스트나 데이터 규모가 큰 실무에서는 스택 제한과 속도를 고려해 **Bottom-up(Tabulation) 방식을 더 기본적이고 안정적인 방법으로 권장**합니다.

### 📌 [Q5] 분할 정복과 DP의 차이는? 언제 DP를 사용해야 하는가?

두 기법 모두 "문제를 작게 쪼개서 푼다"는 공통점이 있습니다. 핵심적인 결정적 차이는 **부분 문제의 중복 여부**입니다.
- **분할 정복 (Divide and Conquer)**: 쪼개진 부분 문제들이 서로 독립적이며 한 번 풀면 다시 발생하지 않습니다. 즉, 결괏값을 저장하고 재사용(캐싱)할 필요가 없습니다. (예: 병합 정렬, 퀵 정렬)
- **동적 프로그래밍 (DP)**: 쪼개진 부분 문제들이 반복해서 여러 번 중복 발생합니다. 따라서 엄청난 수의 중복 계산을 막기 위해 결과를 캐싱(저장)하여 재사용하는 과정을 거칩니다.
- **DP 사용 시기**: 문제에 '최적 부분 구조'가 존재하는 것을 확인했고, 부분 문제들이 계속해서 중복 발생하여 단순 재귀로 모든 경우를 다 탐색하려고 할 때 **'시간 초과'가 필연적으로 발생할 것으로 예상되는 경우** DP를 사용하여 연산량을 기하급수적에서 다항 시간 수준으로 확연히 낮출 때 사용합니다.

### 📌 [Q6] DP 문제를 풀 때 점화식을 세우는 과정은?

DP로 문제를 해결할 때는 보통 다음의 단계적인 사고 과정을 거칩니다.
1. **상태 정의하기**: 부분 문제를 어떻게 정의할 것인지, 즉 배열이나 DP 테이블의 요소 `dp[i]` (또는 `dp[i][j]`)가 어떤 의미를 가지는지를 명확히 규정합니다. (ex: "i번째 계단까지 도달하는 최소 비용")
2. **종료 조건 및 초기값(Base Case) 설정**: 가장 작은 부분 문제들, 즉 더 이상 쪼갤 수 없는 시작점이나 가장 단순한 상태들의 초기값을 설정하여 시작 포인트를 세웁니다. (ex: `dp[1] = 1, dp[2] = 2`)
3. **상태 전이 방정식(점화식) 도출**: 임의의 목표 상태 `dp[n]`을 구하기 위해, 그 이전에 미리 구해둔 더 작은 문제들의 해들(예를 들면 `dp[n-1]`, `dp[n-2]` 등)을 어떠한 규칙이나 공식으로 결합해 연산할 수 있는지 패턴과 관계식을 찾습니다. (ex: `dp[n] = dp[n-1] + dp[n-2]`)
4. **구현 (Bottom-up / Top-down)**: 도출된 점화식을 바탕으로 문제의 제약 조건 등을 고려하여 타뷸레이션(for문) 또는 메모이제이션(재귀함수) 중 적절한 방식을 하나 선택하여 코드로 작성합니다.
