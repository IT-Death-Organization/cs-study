## Q1. 동적 프로그래밍이란 무엇이며 어떤 문제에 적용 가능한가?

[답변]
	•	동적 프로그래밍(Dynamic Programming, DP)은 큰 문제를 작은 부분 문제로 나누고, 그 부분 문제의 답을 저장하여 다시 활용함으로써 전체 문제를 효율적으로 해결하는 알고리즘 기법
	•	이미 계산한 값을 반복해서 다시 구하지 않기 때문에, 단순 재귀나 완전 탐색보다 시간 복잡도를 크게 줄일 수 있음
	•	DP는 특히 다음과 같은 문제에 적용 가능
	•	최적화 문제: 최소 비용, 최대 이익, 최단 거리, 최대 부분합 등
	•	경우의 수 계산 문제: 특정 조건을 만족하는 방법의 수 세기
	•	가능 여부 판단 문제: 만들 수 있는지, 도달 가능한지 여부 확인
	•	수열/배열 기반 문제: LIS, LCS, 배낭 문제, 계단 오르기 등
	•	즉, 부분 문제의 결과를 재사용할 수 있는 구조를 가진 문제에 적합

## Q2. DP의 두 가지 조건(최적 부분 구조, 중복 부분 문제)을 설명하면?

[답변]
* DP가 적용되기 위해 주로 확인하는 두 가지 조건
	1.	최적 부분 구조(Optimal Substructure)
	  -	큰 문제의 최적해가 작은 부분 문제들의 최적해로부터 구성될 수 있는 성질
   	-	즉, 전체 문제를 잘 풀기 위해 부분 문제도 잘 풀면 됨
   	-	예를 들어 최단 경로 문제에서, A에서 C까지의 최단 경로가 A→B→C라면, A에서 B까지와 B에서 C까지도 각각 최단 경로여야 함
  2. 중복 부분 문제(Overlapping Subproblems)
    - 동일한 부분 문제가 여러 번 반복해서 등장하는 성질입니다.
    - 예를 들어 피보나치 수열에서 f(5)를 구할 때 f(3), f(2) 등이 여러 번 반복 호출
    - 이런 경우 계산 결과를 저장해 두면 중복 계산을 줄일 수 있음

## Q3. Memoization(Top-down)과 Tabulation(Bottom-up)의 차이는?

[답변]
* 두 방식 모두 DP, but 계산을 진행하는 방향과 구현 방식이 다름
	1.	Memoization (Top-down)
	•	큰 문제부터 시작해서, 필요한 작은 문제를 재귀적으로 호출하며 내려가는 방식
	•	한 번 계산한 결과는 메모리에 저장해 두고, 다음에 같은 문제가 나오면 저장된 값을 바로 사용
	•	“필요한 것만 계산한다”는 특징이 있음
	2.	Tabulation (Bottom-up)
	•	가장 작은 문제부터 시작해서, 차례대로 테이블을 채우며 큰 문제로 올라가는 방식
	•	보통 반복문을 사용하여 dp[0], dp[1], dp[2] … 순으로 계산
	•	전체 상태를 순서대로 계산하는 구조

## Q4. 각 방식의 장단점은? 어떤 경우에 어떤 방식을 선택하는가?

[답변]
* Memoization (Top-down)의 장점
	•	점화식을 그대로 재귀 형태로 표현하기 쉬워서 직관적
	•	필요한 상태만 계산하므로, 전체 상태를 모두 채울 필요가 없는 경우 효율적
	•	문제 구조를 처음 설계할 때 접근이 쉬움
* Memoization (Top-down)의 단점
	•	재귀 호출을 사용하므로 호출 스택 부담이 있음
	•	입력이 크면 스택 오버플로우 위험이 있음
	•	함수 호출 오버헤드가 발생할 수 있음
* Tabulation (Bottom-up)의 장점
	•	반복문 기반이라 재귀 스택 문제가 없음
	•	일반적으로 실행 속도가 더 안정적이고 빠른 편
	•	메모리 최적화(예: 이전 값 몇 개만 유지)가 쉬운 경우가 많음
* Tabulation (Bottom-up)의 단점
	•	계산 순서를 스스로 정해야 하므로 설계가 더 어렵게 느껴질 수 있음
	•	실제로 필요하지 않은 상태까지 모두 계산할 수 있음
	•	점화식은 맞아도 테이블 채우는 순서를 잘못 잡으면 오류가 발생할 수 있음
* 선택 기준
	•	문제 구조를 빠르게 파악하고 구현하고 싶으면 Top-down
	•	입력이 크고 성능이나 안정성이 중요하면 Bottom-up
	•	전체 상태를 순서대로 자연스럽게 정의할 수 있으면 Bottom-up
	•	일부 상태만 필요하고 재귀 구조가 명확하면 Top-down

## Q5. 분할 정복과 DP의 차이는? 언제 DP를 사용해야 하는가?

[답변]
1.	분할 정복
	•	문제를 작은 문제로 나누어 각각 독립적으로 해결한 뒤 결합
	•	부분 문제가 서로 겹치지 않는 경우가 많음
	•	대표 예: 병합 정렬, 퀵 정렬, 이진 탐색
2.	동적 프로그래밍
	•	문제를 작은 부분 문제로 나누는 것은 같지만, 동일한 부분 문제가 반복해서 등장
	•	따라서 계산 결과를 저장하고 재사용하는 것이 핵심
	•	대표 예: 피보나치, 배낭 문제, LCS

## Q6. DP 문제를 풀 때 점화식을 세우는 과정은?

[답변]
1.	상태(State)를 정의한다
	•	무엇을 기준으로 부분 문제를 나눌지 정함
	•	예: dp[i] = i번째까지 고려했을 때의 최적값
	•	예: dp[i][j] = i번째 물건까지 고려하고, 무게 한도가 j일 때의 최대 가치
2.	점화식(Transition)을 찾는다
	•	현재 상태가 이전 상태들로부터 어떻게 계산되는지 관계를 세움
	•	예: dp[i] = dp[i-1] + dp[i-2]
	•	예: 현재 원소를 선택하는 경우 / 선택하지 않는 경우로 나누기
3.	초기값(Base Case)을 정한다
	•	가장 작은 문제의 답을 먼저 명확히 정함
	•	예: dp[0] = 0, dp[1] = 1
4.	계산 순서를 정한다
	•	Bottom-up이면 어떤 순서로 테이블을 채울지 정함
	•	Top-down이면 어떤 종료 조건으로 재귀를 멈출지 정함
5.	중복 계산 여부와 자료구조를 점검
	•	배열, 2차원 배열, 해시맵 등 어떤 저장 구조를 쓸지 결정

=> 결국 점화식은 “현재 문제를 해결하기 위해 바로 이전의 어떤 결과가 필요한가?”를 식으로 표현한 것
