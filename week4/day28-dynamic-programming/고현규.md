# 1. 동적 프로그래밍이란 무엇이며 어떤 문제에 적용 가능한가?

> 동적 프로그래밍(Dynamic Programming, DP)은 복잡한 문제를 여러 작은 부분 문제로 나누어 해결한 뒤 결과를 저장했다가 나중에 필요할 때 재사용하는 기법입니다.

Dynamic이라는 이름은 특별한 공학적 의미는 없고 이 알고리즘을 창시한 리처드 벨만이 단지 이름이 멋있어 보여서 혹은 연구비를 따기 위해 붙였다는 일화가 유명하죠.

Programming의 "코드 작성" 보단 표를 채워나가는 방식 혹은 계획법으로 이해하는 것이 훨씬 정확합니다.

핵심 아이디어는 "기억하며 풀기" 입니다. 이러한 동적 프로그래밍은 최적화 문제, 경우의 수 계산 문제, 결정 문제에 적용 가능합니다.

* 최적화 문제: 여러 선택지 중 최댓값이나 최솟값을 구히야 하는 문제입니다. (배낭 문제, 최단 경로)
* 경우의 수 문제: 특정 지점에 도달하는 방법의 가짓수를 구하는 문제입니다. (계단 오르기)
* 결정 문제: 특정 조건을 만족하는 해가 존재하는지 확인하는 문제입니다.

DP의 본질은 메모리를 좀 더 써서 시간을 절약하는 것입니다. 풀면서 적어두는 실시간 최적화 전략이라고 볼 수 있죠.

# 2. DP의 두 가지 조건(최적 부분 구조, 중복 부분 문제)을 설명하면?

> DP가 성립하려면 최적 부분 구조와 중복 부분 문제의 두 가지 조건이 필요합니다.

### 최적 부분 구조 (Optimal Substructure)

* 정의
    * 큰 문제의 최적해가 작은 문제들의 최적해를 결합해 만들어지는 구조입니다.

* 핵심
    * 작은 문제의 정답이 큰 문제에서도 여전히 정답인지를 학인하는 것입니다.

* 예시
    * 서울에서 부산까지 가는 최단 경로를 찾을 때, 대전을 거쳐 간다면 '서울-대전'의 최단 경로와 '대전-부산'의 최단 경로의 합이 곧 전체 최단 경로가 됩니다. 작은 구간의 최단 거리가 전체의 최단 거리를 구성하는 부품이 되는 셈이죠.

### 중복 부분 문제 (Overlapping Subproblems)

* 정의
    * 동일한 작은 문제들이 반복해서 나타나는 경우를 말합니다.

* 핵심
    * 방금 푼 문제를 또 풀고있는지 확인하는 것입니다.

* 예시
    * 대표적으로 피보나치 수열을 구하는 것이 있습니다.
    * $F(5) = F(4) + F(3)$
    * $F(4) = F(3) + F(2)$
    * $F(5)$를 구할 때도, $F(4)$를 구할 때도 $F(3)$이 중복적으로 필요합니다. 이걸 저장해두고 사용하는 것입니다.

# 3. Memoization(Top-down)과 Tabulation(Bottom-up)의 차이는?

> DP를 구현할 때 Top-down과 Bottom-up 방식이 있습니다. 둘은 서로 문제를 바라보는 방향 자체가 정반대입니다.

### Memoization(Top-down)

재귀(Recursion)를 사용합니다.

피보나치 예시를 사용하자면, $F(n)$을 구할 때 $F(n-1)$과 $F(n-2)$가 구해져있는지 확인하고 없다면 하나 더 밑으로 내려가서 계산해오는 방식입니다.

핵심은 메모이제이션입니다. 한 번 계산한 결과는 배열이나 해시맵에 메모해두고 다시 필요할 때 즉시 반환됩니다.

### Tabulation (Bottom-up)

반대로 반복문을 사용합니다.

Memoization과 반대로 $F(0), F(1)$부터 시작해서 순서대로 계산하며 표를 채워나가는 방식입니다.

핵심은 타불레이션(Tabulation)입니다. 작은 문제부터 시작해서 빈틈없이 표를 채웁니다.

<br>

| 구분 | Memoization (Top-down) | Tabulation (Bottom-up) |
| :--- | :--- | :--- |
| **주요 도구** | 재귀 (Recursion) | 반복문 (Loop) |
| **풀이 방향** | 큰 문제 $\rightarrow$ 작은 문제 | 작은 문제 $\rightarrow$ 큰 문제 |
| **특징** | 점화식을 그대로 코드로 옮기기 쉬움 | 초기값부터 차례대로 채우므로 직관적임 |
| **위험 요소** | 재귀 깊이 제한 (Stack Overflow) | 모든 부분 문제를 다 풀어야 함 (불필요한 계산 발생 가능) |

<br>

우리가 머리로 생각하기엔 Top-down이 더 직관적이라 코테에서는 이 방법으로 접근을 많이 하지만 컴퓨터는 Bottom-up이 더 효율적이라 효율성과 안전성을 고려한다면 Bottom-up을 사용하는 것이 좋습니다.

# 4. 각 방식의 장단점은? 어떤 경우에 어떤 방식을 선택하는가?

> 방금 말했듯, 코드의 직관성 vs 시스템의 안정성입니다.

### Memoization의 장단점

**장점**

직관적이고, 점화식을 코드로 옮기기 쉽습니다.

모든 하위 문제를 풀 필요가 없을 때 실제로 호출되는 부분만 계산하므로 효울적입니다.

**단점**

재귀 깊이가 너무 깊어지면 StackOverflowError가 발생할 수 있습니다. (특히 파이썬처럼 재귀 제한이 엄격하면 치명적일 수 있습니다.)

함수를 반복해서 호출하므로 비용이 들어서 Bottom-up보다 약간 느릴 수 있습니다.

### Tabulation의 장단점

**장점**

반복문이기 때문에 오버헤드가 적고, StackOverflow 위험이 없습니다.

또한 메모리에 순차적으로 접근하기 때문에 캐시 히트에 유리해 속도가 매우 빠릅니다.

**단점**

모든 부분 문제를 다 풀어야 하기 때문에 불필요한 계산이 발생할 수 있습니다.

Memoization의 점화식 작성보다 구현이 더 복잡할 수 있습니다.

### 선택 방식

* Top-down
    * 문제가 복잡해 점화식을 코드로 바로 옮겨야 할 때
    * 일부만 탐색해도 답이 나올 때

* Bottom-up
    * 성능이 중요할 때
    * 범위가 커서 재귀가 깊어질 때
    * 보통 코테에선 이게 더 안전한 선택입니다.

# 5. 분할 정복과 DP의 차이는? 언제 DP를 사용해야 하는가?

> 둘 다 큰 문제를 작은 문제로 나누지만, 분할 정복은 부분 문제가 겹치지 않고, DP는 부분 문제가 겹쳐서 결과를 저장해 재사용한다는 점이 다릅니다.

### 분할 정복 (Divide and Conquer)

큰 문제를 작은 부분 문제로 나눕니다.

각 부분 문제는 서로 독립적입니다. 한 부분 문제의 결과가 다른 부분 문제에서 다시 쓰이지 않습니다.

대표적으로 병합 정렬, 퀵 정렬, 이진 탐색이 있습니다. 예를 들어 병합 정렬에서 왼쪽 절반 정렬과 오른쪽 절반 정렬은 서로 다른 데이터를 다루므로 겹치지 않습니다.

### DP (Dynamic Programming)

이것 역시 큰 문제를 작은 부분 문제로 나눕니다.

하지만 같은 부분 문제가 여러 번 나타납니다. 그래서 한 번 계산한 결과를 저장해 두었다가 재사용합니다.

피보나치에서 $F(3)$이 $F(5)$를 구할 때도, $F(4)$를 구할 때도 필요했던 것처럼 말이죠.

### 정리

| 구분 | 분할 정복 | DP |
| :--- | :--- | :--- |
| **부분 문제** | 서로 독립적 (겹침 없음) | 겹침 있음 (중복 부분 문제) |
| **결과 저장** | 보통 안 함 | 메모이제이션/타불레이션으로 저장 |
| **예시** | 병합 정렬, 이진 탐색 | 피보나치, 배낭 문제, LCS |

### 언제 DP를 써야 하나

문제를 쪼갰을 때 같은 작은 문제가 반복해서 나오는지 봅니다. 그렇다면 재귀만 쓰면 비효율적이니까 DP를 의심해 보는 게 좋습니다.

그리고 최적 부분 구조가 있으면 (작은 문제의 최적해가 큰 문제의 최적해에 그대로 쓰이면) DP로 풀 수 있습니다.

"이 상태에서 저 상태로 가는 경우의 수/최적값"을 묻는 문제, 또는 재귀 점화식은 세우겠는데 호출이 중복되는 느낌이 들면 DP로 바꿔 보면 됩니다.

# 6. DP 문제를 풀 때 점화식을 세우는 과정은?

### 1. DP 테이블 정의

`dp[i]`가 무엇을 의미하는지 정의합니다.

예를 들어 피보나치 수열을 푼다고 하면, `dp[i]`는 i번째 피보나치 수를 의미합니다.

### 2. 점화식 찾기

`dp[i]`를 구하기 위해 바로 직전 단계들(`dp[i-1]`, `dp[i-2]`)과 어떤 관계인지 파악합니다.

피보나치 수열의 경우 `dp[i] = dp[i-1] + dp[i-2]` 입니다.

### 3. 초기값 설정

점화식이 작동하기 위해 필요한 작은 단위의 값들을 미리 정의합니다.

피보나치 수열의 경우 `dp[0] = 0`, `dp[1] = 1` 입니다.
