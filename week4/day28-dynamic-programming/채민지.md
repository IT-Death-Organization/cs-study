## 1. 동적 프로그래밍이란 무엇이며 어떤 문제에 적용 가능한가?

> 동적 프로그래밍은 복잡한 문제를 작은 부분 문제로 나누고, 그 결과를 저장해 **중복 계산을 제거**하는 알고리즘 설계 기법입니다.
> 

핵심은 **'한 번 푼 문제는 다시 풀지 않는다**'는 점이며, 이를 위해 계산된 값을 메모리에 저장하는 **메모이제이션(Memoization)**을 주로 활용합니다.

### 1-1. 어떤 문제에 적용 가능한가 ?

다음과 같은 성질을 동시에 가진 문제에 효과적입니다.

1. **중복되는 부분 문제 (Overlapping Subproblems):** 동일한 작은 문제들이 반복해서 나타나는 경우입니다. (ex. 피보나치 수열 계산)
2. **최적 부분 구조 (Optimal Substructure):** 전체 문제의 최적해가 부분 문제들의 최적해를 통해 구해질 수 있는 경우입니다. (ex. 최단 경로 찾기)

### 대표적인 활용 사례

- **배낭 문제 (Knapsack Problem):** 한정된 무게 내에서 가치를 최대화하는 조합 찾기
- **최단 경로 문제:** 플로이드-워셜 알고리즘 등
- **LCS (Longest Common Subsequence):** 두 문자열 사이의 가장 긴 공통 부분 수열 찾기
- **편집 거리 (Edit Distance):** 한 문자열을 다른 문자열로 바꾸는 최소 연산 횟수 계산

## 2. DP의 두 가지 조건(최적 부분 구조, 중복 부분 문제)을 설명하면?

### 2-1. **최적 부분 구조**

: 큰 문제의 **최적의 답**이 그 안에 포함된 작은 문제들의 **최적의 답**을 모아서 만들어지는 구조를 말합니다. 즉, 전체 문제를 해결하기 위해 부분 문제의 답을 구했을 때, **그 답들이 변하지 않고 그대로 전체 문제의 구성 요소가 되는 것**입니다.

ex. 서울 ~ 부산까지 가는 최단 경로는 **‘서울 → 대구’의 최단 경로와 ‘대구 → 부산’의 최단 경로의 합**으로 이루어지는 것과 같음

### 2-2. **중복되는 부분 문제**

: 문제를 해결하는 과정에서 **동일한 작은 문제들이 반복적으로 호출**되는 경우입니다. 즉, 아까 계산했던 것을 조금 뒤에 또 계산해야 하는 상황입니다.

ex. 피보나치 수열에서 `f(5)`를 구할 때 `f(3)`이 필요하고, `f(4)`를 구할 때도 `f(3)`이 중복해서 사용됩니다. DP는 이때 매번 새로 계산하는 대신 저장된 값을 꺼내 써서 효율을 높입니다.

⇒ 이 두 조건이 충족될 때, 단순 재귀보다 훨씬 빠른 속도로 문제를 해결할 수 있습니다.

## 3. Memoization(Top-down)과 Tabulation(Bottom-up)의 차이는?

### 3-1. Memoization (Top-down)

> **재귀적으로** 큰 문제를 작은 문제로 쪼개고, 각 문제의 답을 **메모이제이션**을 통해 저장하는 방식(위에서 아래로, 큰 문제 → 작은 문제)
> 

```python
public static long fib(int n) {
        if (n == 0) return 0;
        if (n == 1) return 1;
        if (memo[n] != 0) return memo[n]; // 이미 계산한 값은 재사용
        memo[n] = fib(n - 1) + fib(n - 2); // 재귀 호출
        return memo[n];
    }

```

- 큰 문제를 **재귀적으로 나누고**, 중복되는 계산을 방지하기 위해 계산된 값을 저장합니다.
- 필요한 부분만 계산하므로 효율적이지만, 재귀 호출로 인해 스택 오버헤드가 발생할 수 있습니다.

### 재귀적 방식 (메모이제이션 없이)과의 비교

```python
public static long fib(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return fib(n - 1) + fib(n - 2); // 중복 계산 발생
}
```

- **중복되는 계산이 많아** 성능이 매우 떨어집니다.
- 예를 들어 `fib(5)`를 계산할 때 `fib(3)`을 두 번 계산하는 등 중복이 심합니다.

### 3-2. Tabulation(Bottom-up)

> **작은 문제부터** 해결해 나가면서, 그 결과를 저장하여 큰 문제를 해결하는 방식 (아래에서 위로, 작은 문제 → 큰 문제)
> 

```python
long[] dp = new long[n + 1]; // n번째 피보나치 수를 저장할 배열
        dp[0] = 0;
        dp[1] = 1;

        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2]; // 차례로 값을 구함
        }
```

- 작은 문제부터 해결해나가며 모든 값을 구합니다.
- 재귀호출 없이 **반복문을 사용**하므로 재귀 호출이 없어 스택 오버헤드가 발생하지 않습니다.

| **구분** | **Memoization (Top-down)** | **Tabulation (Bottom-up)** |
| --- | --- | --- |
| **핵심 도구** | 재귀 (Recursion) | 반복문 (For-loop) |
| **저장 방식** | 필요한 것만 계산 후 저장 | 밑바닥부터 모두 계산하여 저장 |
| **장점** | 직관적이고 코드가 깔끔함 | 실행 속도가 빠르고 안정적임 |
| **단점** | 스택 오버플로 위험 | 모든 중간값을 계산해야 함 |

## 4. 각 방식의 장단점은? 어떤 경우에 어떤 방식을 선택하는가?

### 4-1. 각 방식의 장단점

| **방식** | **장점** | **단점** |
| --- | --- | --- |
| **Memoization** (Top-down) | 1. 필요한 부분 문제만 계산하므로 **불필요한 연산**이 줄어듭니다.2. 문제의 정의를 그대로 코드로 옮기기 좋아 **직관적**입니다. | 1. **재귀 호출**로 인한 시스템 스택 메모리 사용량이 많습니다.2. 깊이가 너무 깊으면 **스택 오버플로**가 발생합니다. |
| **Tabulation** (Bottom-up) | 1. 반복문을 사용하므로 **실행 속도**가 상대적으로 빠릅니다.2. 스택 오버플로 걱정 없이 **안정적**입니다. | 1. 하위 문제의 결과가 전체에 필요 없더라도 **순서대로 모두 계산**해야 합니다.2. 테이블을 채우는 순서를 파악하는 논리가 필요합니다. |

### 4-2. 어떤 경우에 어떤 방식을 선택하나 ?

### **Memoization(Top-down)을 선택할 때**

- **부분 문제의 수가 많지만, 실제 전체 문제를 푸는 데 필요한 부분 문제는 적을 때:** 모든 하위 문제를 풀 필요가 없으므로 훨씬 빠릅니다.
- **재귀 구조가 훨씬 직관적일 때:** 알고리즘 설계 단계에서 로직을 빠르게 검증하고 싶을 때 유리합니다.

### **Tabulation(Bottom-up)을 선택할 때**

- **모든 부분 문제를 전부 해결해야 할 때:** 어차피 다 풀어야 한다면 재귀 비용이 없는 반복문이 성능 면에서 압도적입니다.
- **성능 최적화가 중요할 때:** 함수 호출 오버헤드가 없으므로 시간과 메모리 효율을 극대화할 수 있습니다.
- **재귀 깊이(Recursion Depth) 제한이 있는 환경:** 파이썬처럼 기본 재귀 한도가 낮은 언어에서 안전하게 구현하고 싶을 때 사용합니다.

> **결론적으로**, **처음 접근할 때**는 **Top-down**으로 로직을 짜보고, 만약 **시간 초과나 메모리 제한(스택 오버플로)**에 걸린다면 **Bottom-up**으로 전환하는 것이 일반적인 전략입니다.
> 

## 5. 분할 정복과 DP의 차이는? 언제 DP를 사용해야 하는가?

분할 정복과 DP는 모두 큰 문제를 작은 문제로 나누어 푸는 방식이지만, **작은 문제의 중복 여부**에서 결정적인 차이가 갈립니다.

### 5-1. 분할 정복 vs DP 차이점

| **구분** | **분할 정복 (Divide & Conquer)** | **동적 프로그래밍 (DP)** |
| --- | --- | --- |
| **부분 문제 관계** | 부분 문제가 서로 **독립적**임 | 부분 문제가 **중복**됨 (서로 얽혀 있음) |
| **재계산 여부** | 동일한 계산을 반복하지 않음 (한 번만 함) | 동일한 계산이 반복되어 **결과를 저장(Memo)**함 |
| **대표 사례** | 퀵 정렬, 병합 정렬, 이진 탐색 | 피보나치, 배낭 문제, 최단 경로 |
- **분할 정복**은 문제를 쪼개서 각각 해결하고 합치는 데 집중합니다. (나눠진 조각들이 서로 영향을 주지 않음)
- **DP**는 쪼개진 문제들이 서로 겹치기 때문에, 한 번 구한 답을 재사용하는 데 집중합니다.

### 5-2. 언제 DP를 사용해야 하는가 ?

문제를 풀 때 다음 **두 가지 신호**가 포착되면 DP 도입을 검토해야 합니다.

1. **중복된 계산이 보일 때:** 재귀로 풀었을 때 동일한 인자값으로 함수가 여러 번 호출되는 경우입니다.
2. **최적화 문제일 때:** '최댓값', '최솟값', '경우의 수'를 구하라는 문제에서, 큰 문제의 답이 작은 문제들의 조합으로 만들어질 때입니다.

## 6. DP 문제를 풀 때 점화식을 세우는 과정은?

### **6-1. 상태(State) 정의하기**

먼저 "무엇을 DP 테이블에 저장할 것인가?"를 결정해야 합니다. 문제에서 구하고자 하는 최종 목표를 문장으로 정의해 보세요.

- **예:** `dp[i]` = i번째 계단까지 올라왔을 때 얻을 수 있는 최대 점수
    
    [](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)
    
- **팁:** 변수(인덱스)가 하나면 1차원 배열, 두 개(예: 물건 번호와 무게)면 2차원 배열이 필요합니다.

### **6-2. 점화식(Relation) 세우기**

현재 단계의 답을 이전 단계들의 답으로 어떻게 만들 수 있는가를 고민하는 단계입니다. **마지막 순간**을 가정해 보면 쉽습니다.

- **생각의 흐름:** i번째 칸에 오기 직전에는 어디에 있었을까? 바로 직전(i-1)일까, 아니면 두 칸 전(i-2)일까?
    
    [](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)
    
    [](data:image/gif;base64,R0lGODlhAQABAIAAAP///wAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==)
    
- **식 세우기:** `dp[i] = max(dp[i-1], dp[i-2]) + score[i]` (이런 식으로 선택지를 식으로 옮깁니다.)

### **6-3. 초기 상태(Base Case) 설정하기**

가장 작은 문제, 즉 더 이상 쪼개지지 않는 지점의 값을 미리 정해줍니다. 이 값이 있어야 점화식이 출발할 수 있습니다.

- **예:** `dp[0] = 0`, `dp[1] = score[1]`
- **주의:** 문제 조건에 따라 0번 인덱스나 1번 인덱스를 어떻게 처리할지 명확히 해야 합니다.

### **6-4. 계산 순서 정하기 (구현)**

- **Bottom-up:** `for`문을 돌리며 `dp[1]`부터 `dp[n]`까지 차례대로 채웁니다.
- **Top-down:** 재귀 함수를 호출하며 결과가 나오면 메모이제이션합니다.
