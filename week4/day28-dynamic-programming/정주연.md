## 동적 프로그래밍이란 무엇이며 어떤 문제에 적용 가능한가?

- 큰 문제를 작은 문제로 쪼개어 나가면서 문제를 해결 → 그 답을 메모리에 저장(Caching)하여 동일한 하위 문제의 재계산을 방지하는 알고리즘
- 어떤 문제에?
    - 최적화 문제(최댓값, 최솟값 구하기)
    - 경우의 수를 구하는 문제
    
    계산량이 기하급수적으로 늘어나는 문제를 다항 시간 내에 풀 수 있게 해줌
    

## DP의 두 가지 조건(최적 부분 구조, 중복 부분 문제)을 설명하면?

- 최적 부분 구조 (Optimal Substructure)
    - 큰 문제의 최적해가 작은 문제들의 최적해들로부터 구성될 수 있는 구조
    - 작은 문제에서 구한 정답이 큰 문제에서도 그대로 사용되어야 함
- 중복 부분 문제 (Overlapping Subproblems)
    - 동일한 작은 문제들이 반복적으로 나타나는 경우
    - 단순히 문제를 나누는 것에서 그치지 않고, 똑같은 계산을 여러 번 수행해야 할 때 DP의 효율성이 극대화

## Memoization(Top-down)과 Tabulation(Bottom-up)의 차이 및 장단점

| **구분** | **Memoization (Top-down)** | **Tabulation (Bottom-up)** |
| --- | --- | --- |
| **방식** | 재귀(Recursion) 기반 | 반복문(Iteration) 기반 |
| **흐름** | 큰 문제에서 작은 문제로 내려감 | 작은 문제부터 차례로 쌓아 올라감 |
| **저장 방식** | 필요한 결과만 계산하여 저장(Memo) | 테이블을 처음부터 끝까지 채움(Table) |
| **장점** | 직관적이며 모든 하위 문제를 풀 필요가 없음 | 스택 오버플로우 위험이 없고 시간 효율적임 |
| **단점** | 재귀 깊이 제한에 걸릴 수 있음 | 필요 없는 하위 문제까지 모두 계산할 수 있음 |

## 분할 정복과 DP의 차이는? 언제 DP를 사용해야 하는가?

- 분할 정복
    - 하위 문제들이 서로 중복되지 않음
    - ex) 퀵 정렬, 병합 정렬
    - 한 번 푼 문제를 다시 풀 일이 없으므로 결과를 저장할 필요가 없음
- DP
    - 하위 문제들이 서로 중복됨
    - 결과를 저장(Memoization)하는 과정이 필수적임
- 언제?
    - 문제를 나누었을 때 똑같은 계산이 반복된다면 DP를, 그렇지 않다면 분할 정복을 선택함

## DP 문제를 풀 때 점화식을 세우는 과정은?

- 상태 정의
    - dp[n]이 무엇을 의미하는지 문장으로 정의
- 기저 상태(Base Case) 찾기
    - 가장 작은 단위의 답을 구함 (ex. dp[0]=0)
- 상태 전이 관계 찾기
    - n번째 단계의 답을 얻기 위해 n−1,n−2… 단계의 답을 어떻게 조합할지 규칙을 찾음
- 점화식 작성
    - 찾은 규칙을 수식으로 표현함
