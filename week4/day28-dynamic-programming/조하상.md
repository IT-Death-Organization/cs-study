## 1. 동적 프로그래밍이란 무엇이며 어떤 문제에 적용 가능한가?

**기억하며 풀기**
- 복잡한 문제를 여러 개의 작은 하위 문제로 나누어 풀고, 그 결과를 저장했다가 다시 사용하는 최적화 기법이다. 
- 한 번 계산한 문제를 다시 계산하지 않도록 하여 시간 복잡도를 획기적으로 줄이는 것이 핵심이다. 주로 최댓값/최솟값을 구하는 최적화 문제나 경우의 수를 세는 문제에 적용 가능하다.

---

## 2. DP의 두 가지 조건(최적 부분 구조, 중복 부분 문제)



- **최적 부분 구조 (Optimal Substructure):** 큰 문제의 최적해(정답)가 작은 문제들의 최적해를 결합하여 얻어질 수 있는 구조를 말한다. 예를 들어, $f(n) = f(n-1) + f(n-2)$처럼 이전 단계의 결과로 현재 단계를 설명할 수 있어야 한다.
- **중복 부분 문제 (Overlapping Subproblems):** 동일한 작은 문제들이 반복적으로 나타나는 구조를 말한다. 같은 계산을 여러 번 수행해야 할 때, 결과를 저장해두는 DP의 효율성이 극대화된다.

---

## 3. Memoization(Top-down)과 Tabulation(Bottom-up)의 차이는?

- **Memoization (Top-down):** 큰 문제를 해결하기 위해 작은 문제를 호출하는 방식이다. 주로 **재귀(Recursion)**를 사용하며, 계산된 결과를 배열이나 맵에 저장(Memo)해두었다가 필요할 때 꺼내 쓴다.
- **Tabulation (Bottom-up):** 가장 작은 문제부터 차례대로 해결하며 테이블을 채워나가는 방식이다. 주로 **반복문(Iteration)**을 사용하며, 아래에서부터 위로 쌓아 올린다는 의미에서 타뷸레이션이라고 부른다.

## 4. 각 방식의 장단점과 선택 기준

| 방식 | 장점 | 단점 |
| :--- | :--- | :--- |
| **Top-down** | 코드 가독성이 좋고, 필요한 부분만 계산하므로 경우에 따라 빠를 수 있다. | 재귀 깊이가 너무 깊어지면 스택 오버플로우(Stack Overflow)가 발생할 수 있다. |
| **Bottom-up** | 반복문을 사용하므로 스택 오버플로우 걱정이 없고 시간/공간 효율성이 더 정밀하다. | 모든 하위 문제를 순차적으로 계산해야 하므로 가독성이 떨어질 수 있다. |

**선택 기준:** 스택 깊이에 제한이 있는 환경이라면 **Bottom-up**을 권장하며, 문제의 점화식이 직관적으로 재귀와 어울린다면 **Top-down**을 우선 고려한다.

## 5. 분할 정복과 DP의 차이는?

**하위 문제의 중복 여부**
- **분할 정복 (Divide and Conquer):** 큰 문제를 작은 문제로 나누어 풀지만, 나뉘는 하위 문제들이 서로 겹치지 않는다. (예: 퀵 정렬, 병합 정렬)
- **DP:** 나뉘는 하위 문제들이 서로 겹치며 중복된다. 따라서 저장된 결과를 재활용하느냐가 두 기법을 가르는 가장 큰 차이점이다. 하위 문제가 반복될 때만 DP를 사용한다.

## 6. DP 문제를 풀 때 점화식을 세우는 과정은?

점화식(Recurrence Relation)은 DP의 핵심이며 다음의 단계를 거쳐 설계한다.
1. **상태 정의:** $dp[i]$가 무엇을 의미하는지 구체적으로 정의한다. (예: $i$번째 계단까지 오르는 최소 비용)
2. **관계 찾기:** 현재 상태 $i$를 만들기 위해 바로 이전 단계($i-1, i-2$ 등)에서 어떤 선택을 해야 하는지 논리적으로 연결한다.
3. **점화식 작성:** 찾아낸 관계를 수식으로 표현한다. (예: $dp[i] = min(dp[i-1], dp[i-2]) + cost[i]$)
4. **기저 상태 설정:** 가장 작은 문제의 초기값($dp[0], dp[1]$ 등)을 설정하여 연산이 시작될 수 있게 한다.
