# 1. Dynamic Programming이란 무엇인가?

**Dynamic Programming (DP)** 은

> **큰 문제를 작은 부분 문제로 나누고, 그 결과를 저장하여 중복 계산을 제거하는 알고리즘 기법**

입니다.

핵심 아이디어

1. 문제를 **부분 문제(subproblem)** 로 분해
2. 부분 문제의 **결과를 저장**
3. 동일한 계산을 **다시 하지 않음**

즉

```
재귀 + 캐싱
```

이라고 이해하면 쉽습니다.

---

## 예시: Fibonacci

일반 재귀

```
F(n) = F(n-1) + F(n-2)
```

재귀 호출 트리

```
F(5)
 ├─ F(4)
 │   ├─ F(3)
 │   │   ├─ F(2)
 │   │   └─ F(1)
 │   └─ F(2)
 └─ F(3)
     ├─ F(2)
     └─ F(1)
```

문제

```
F(3), F(2) 같은 계산이 반복됨
```

DP

```
F(3) 한번 계산 → 저장
다음에 바로 사용
```

시간복잡도

```
재귀 : O(2^n)
DP : O(n)
```

# 2. DP가 가능한 두 가지 조건

DP가 적용되려면 **두 가지 조건**이 필요합니다.

## 1️⃣ Optimal Substructure (최적 부분 구조)

큰 문제의 최적해가
**작은 문제의 최적해로 구성되는 경우**

예

최단 경로

```
A → D 최단경로
A → B → C → D
```

여기서

```
A → C 최단경로
C → D 최단경로
```

이 합쳐져 전체 최적해가 됩니다.

즉

```
global optimum
= subproblem optimum
```

---

## 2️⃣ Overlapping Subproblems (중복 부분 문제)

같은 부분 문제가 **여러 번 반복**되는 경우

예

```
F(5)
F(4)
F(3)
F(3)
F(2)
F(2)
```

중복 발생

→ **DP로 저장하면 해결**

# 3. Memoization vs Tabulation

DP 구현 방식은 두 가지입니다.

| 방식        | 방향      | 구현   |
| ----------- | --------- | ------ |
| Memoization | Top-down  | 재귀   |
| Tabulation  | Bottom-up | 반복문 |

---

# 3.1 Memoization (Top-down)

재귀 호출을 하면서 **결과를 저장**

예

```java
int[] dp = new int[100];

int fib(int n){
    if(n <= 1) return n;

    if(dp[n] != 0) return dp[n];

    dp[n] = fib(n-1) + fib(n-2);
    return dp[n];
}
```

동작

```
필요한 것만 계산
```

---

# 3.2 Tabulation (Bottom-up)

가장 작은 문제부터 **테이블을 채우는 방식**

```java
int fib(int n){
    int[] dp = new int[n+1];

    dp[0] = 0;
    dp[1] = 1;

    for(int i=2;i<=n;i++){
        dp[i] = dp[i-1] + dp[i-2];
    }

    return dp[n];
}
```

동작

```
작은 문제 → 큰 문제
```

---

# 4. Memoization vs Tabulation

| 구분      | Memoization      | Tabulation     |
| --------- | ---------------- | -------------- |
| 구현      | 재귀             | 반복문         |
| 계산      | 필요한 것만 계산 | 모든 상태 계산 |
| 스택 사용 | 있음             | 없음           |
| 직관성    | 높음             | 낮음           |
| 속도      | 약간 느림        | 빠름           |

---

## 언제 어떤 방식 선택?

### Memoization

추천 상황

```
상태 공간이 큰 경우
모든 상태가 필요하지 않을 때
```

예

```
그래프 DP
트리 DP
```

---

### Tabulation

추천 상황

```
모든 상태가 필요
반복문으로 쉽게 표현 가능
```

예

```
LIS
Knapsack
Coin change
```

실무/코딩테스트에서는

```
Bottom-up이 더 많이 사용됨
```

---

# 5. Divide & Conquer vs DP

많이 헷갈리는 부분입니다.

| 구분      | Divide & Conquer | DP        |
| --------- | ---------------- | --------- |
| 부분 문제 | 독립적           | 중복됨    |
| 결과 저장 | 없음             | 있음      |
| 예        | Merge Sort       | Fibonacci |

---

## Divide & Conquer

예

```
Merge Sort
Quick Sort
Binary Search
```

특징

```
subproblem independent
```

예

```
왼쪽 배열 정렬
오른쪽 배열 정렬
```

겹치지 않음

---

## DP

특징

```
subproblem overlapping
```

예

```
F(n-1)
F(n-2)
```

같은 계산 반복

→ 저장 필요

---

# 6. DP 문제를 푸는 과정 (가장 중요)

DP 문제는 항상 **다음 순서로 접근합니다**

---

## 1️⃣ 상태 정의 (State)

먼저

```
dp[i] = 무엇인가?
```

예

Fibonacci

```
dp[i] = i번째 Fibonacci 값
```

LIS

```
dp[i] = i에서 끝나는 LIS 길이
```

---

## 2️⃣ 점화식 (Recurrence)

이전 상태로 현재 상태 표현

예

Fibonacci

```
dp[i] = dp[i-1] + dp[i-2]
```

LIS

```
dp[i] = max(dp[j]) + 1
(j < i, arr[j] < arr[i])
```

---

## 3️⃣ 초기값 (Base case)

예

```
dp[0] = 0
dp[1] = 1
```

---

## 4️⃣ 계산 순서

점화식을 계산할 수 있는 순서

예

```
for i = 2 → n
```

---

# 7. DP 대표 문제 유형

코딩테스트에서 자주 나오는 DP 패턴

| 유형        | 문제                           |
| ----------- | ------------------------------ |
| Linear DP   | Fibonacci                      |
| LIS         | Longest Increasing Subsequence |
| Knapsack    | 배낭 문제                      |
| Coin Change | 동전 문제                      |
| Interval DP | 행렬 곱셈                      |
| Grid DP     | 최소 경로                      |
| Tree DP     | 트리 독립 집합                 |

# 핵심 정리

Dynamic Programming

```
1. 문제를 작은 문제로 분해
2. 중복 계산을 저장
3. 점화식 기반 해결
```

필요 조건

```
1. Optimal Substructure
2. Overlapping Subproblem
```

구현 방식

```
Top-down (Memoization)

```
